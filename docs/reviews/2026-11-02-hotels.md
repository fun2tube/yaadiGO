# Phase 1c, hotels and rate cards: DevOps + PM + CTO review

**Date:** 2026-11-02 · **Spec:** docs/design/ai-cofounder.md §2, §6a

## CTO: what was built

**Tables (migration 0008):**

- `hotels`: name, destination, town, type, stars, contact, phone, email,
  website, address, notes, image, active.
  - One record per property: UNIQUE on lower(name) + lower(town or
    destination).
  - Stars must be 1–5.
- `hotel_rates`: per room per night, by room type, meal plan (EP/CP/MAP/AP)
  and date range. Holds cost, sell, an optional extra-bed cost and sell, and
  a season name. CHECKs:
  - the meal plan is one of the four;
  - the rate does not end before it starts;
  - cost ≥ 0;
  - **sell ≥ cost**;
  - extra-bed sell ≥ extra-bed cost.

**Rules** (`lib/cms/hotels.js`):

- One price per night per room and plan: an overlapping range is refused with
  the clashing dates.
- `priceStay` prices a stay night by night, so a stay crossing seasons is
  priced on each night's own rate. A night with no rate marks the option
  incomplete and names the night; it is never guessed.

**Screens:**

- `/admin/hotels`: directory by destination, cheapest current room, "priced
  to" date, a warning for active hotels with no current rates, search, show
  inactive.
- `/admin/hotels/new` and `/admin/hotels/[id]`: details, then the rate card
  (add, edit, remove; live margin while typing).
- Nav "Hotels" for `catalogue.read` or `quotations.read`. Writes need
  `catalogue.write`.

**Quotation builder:** a new "+ Hotel from directory" picker.

- Choose a hotel, check-in, nights and rooms, then add a room type and meal
  plan as a line:
  - kind hotel;
  - quantity = rooms;
  - sell and cost = the whole stay per room;
  - a detail line with the dates, meal plan and seasons.
- It replaces the empty starter line.
- The line is a snapshot. A later rate change never alters a quotation
  already made.

## Findings

**F1 (S2): the picker opened on an empty list. Fixed.** It pre-filled the
search with the quotation's destination, which is often a trip name
("Kashmir Valley Escape") that matches no hotel's place. Found by using it,
not by the unit tests. The search now starts empty, with hotels in the
trip's destination ranked first.

**F2 (S3): the quotation's "Where you stay" block is not filled from hotel
lines.** The customer-facing hotel list is still typed separately in
Presentation, so the two can disagree. → #200.

**F3 (S3): "no overlapping rates" is enforced in the app, not the
database.** Two people saving overlapping rates in the same second could
both succeed. A `btree_gist` exclusion constraint closes it. Low risk at one
desk. → #201.

**F4 (S3): `hotels.destination` is free text.** It links to a destinations
table when destinations move out of code (1d). → part of 1d.

**F5 (S4): extra-bed and child prices are stored but not used by the
picker.** → #202.
